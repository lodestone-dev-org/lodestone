# Overall Plan

Lodestone is a Minecraft server hosting suite, providing a easy way for anyone to self host a Minecraft server a variety of server software (e.g Paper, Fabric, Neoforge, etc.) While also providing advanced tools and easy feature installation such as web maps, performance dashboards and chunk pre-generation.

Unlike other server panels, Lodestone will have options in the panel for easily installing mods/plugins from curseforge/modrinth/maybe spigot/polymart if we can figure it out, the web map feature is also planned to work by finding and installing the correct bluemap jar for your server, auto configuring it and displaying it in an iframe in the panel and also exposing a secure link to be internet-facing to share the server map with others

The panel will also help beginner server hosts to setup a server, guiding them through server software and auto suggesting java version, RAM to allocate and JVM flags to use, these will be recommended to the user but ultimately they get to pick the values. As an even simpler route we plan to implement preset servers (e.g. survival latest version) which is a one click server install.

To help server owners fix errors and crashes, we plan to integrate a log helper system where logs are analysed using a rule based system but for more detailed log analysis, users will be able to connect an LLM either from a cloud api key or a local model, local model users will be warned if there model is below a certain amount of parameters since its likely to be wrong.

Mods installed through the mod browser will have their compatibility checked and incompatible mods will be hidden by default, if a user searchs for a mod that is hidden, at the bottom of the search results will be an option to display incompatible mods, these mods will still be allowed to be installed but with a disclaimer

Managed Integrations is the name ive come up with for the easy mod setups on the panel such as Bluemap, Chunky and spark are the 3 planned currently, chunky, once installed, will have a config panel allowing a user to set center, radius, shape, world and more and monitor running chunky jobs, all commands and data being sent over RCON, spark will also be added as a way for server owners to monitor there server performance and find the cause of lag

The panel will also feature backups, allowing full automated backups or letting users choose the contents of a backup to save storage, scheduled server restarts can also be performed and players will be alerted in advance using the ingame Minecraft /title commands. Like usual the panel will have a full featured file browser and editor, allowing users to edit config files in a text editor but also containing a structured GUI editor for inexperienced users, the file manager can also show the disk usage of the server with a warning as the server is approaching a full disk. An audit log will also be availible to users with sufficient permissions so when multiple users are using the panel, changes are tracked. We also might plan to support prometheus export of most panel data

The players page will also full player management and moderation, showing player heads and skins using an API, the page will show player data, show moderation options and options to set gamemode, give items and more, playerdata backups are also an option

All running minecraft servers will run inside docker, using RCON to cleanly shut them down, SSE will be used instead of websockets for live console logs

On the backend all servers will run inside docker rather than as children of the Flask process so that restarting or crashing the panel doesn't take the servers down with it, shutdown is done by sending stop over RCON first and only then stopping the container, with console output read out of the container logs and commands going back in over RCON. Shared state will live in redis since multiple workers break anything kept in memory, and long running jobs like backups, installs and pregeneration will be handed off to RQ or celery instead of being run inside a request handler, with SQLAlchemy and alembic handling the database and WAL mode enabled if we stay on SQLite. Sessions will use httpOnly cookies with CSRF protection and user roles stored in the database from the start rather than bolted on later, the file manager will defend against path traversal by resolving the path first and then checking it is still contained in the server directory, we also need to be careful about exposing docker.sock if the panel itself ends up containerised and to keep -Xmx below the container memory limit so the JVM doesn't get killed. Server data will be bind mounted so backups and the file manager can reach it directly, the api will be defined with an OpenAPI contract so the React client can be generated from it, server definitions will be declarative and exportable as YAML for version control and before we build any of this we should look at itzg/minecraft-server since it already solves a lot of the container side
